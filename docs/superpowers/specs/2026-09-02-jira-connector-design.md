# Jira 连接器：插件把单送进来，而不是等你去认领

## 问题

首页现在有 13 张单，而分给你的 Jira 工单有 41 个。差的那 28 个不是 bug——第 1 期定的是「单是内核概念，Jira 只是来源之一，认领是显式动作」，迁移只把**已经开过会话**的 13 个绑定转成了单。

实际用下来这个默认是错的：**「分给我的单」本来就是你要看的东西**，而要求你为 41 个工单逐个点认领，等于把工具的工作交给人。

同时首页一次 Jira 都没访问过。`enrich` 跑在每次页面加载、300ms 硬预算里，明令禁止发网络请求，所以它只能读工单页碰巧填过的缓存——缓存冷的时候，首页上的单连状态和史诗都没有。

要的是：**Jira 成为一个连接器**——它自己去拉，把单送进来，并带回 PR 状态。而这条路要铺得让第二个数据源能顺着走。

## 已定的取舍

六条在设计对话里定死，不再重开：

- **拉回来的工单就落盘**，与本地单同等，不是"显示但不存"的候选。
- **工单从查询结果里消失时什么都不做**——不删、不自动归档，留在那里。（因此必须补手动归档入口，见下。）
- **内核后台定时拉，页面只读已拉好的**。页面永远不等网络。
- **拉取范围由使用者在 Jira 配置里决定**，内核不预设，也不替它加条件。
- **不新增 provider 契约**。插件直接调内核已有的 `ensureItemForSource`，内核只多一个 `start()` 生命周期钩子。
- **PR 状态只给有活跃会话的单拉**。

### 为什么不做 provider 契约

设计对话里先提的是"新增 `provide()` 能力，插件回答我这儿有哪些单，内核负责调度与入库"。它被否掉了，理由是这个仓库自己的规矩：

**「能力面按需要开，不按能想到的开。」** `annotate` 当初因为没有消费者被砍掉，有了真实消费者才开。provider 现在只有一个实现，为它造通用契约是推测性通用化——而第二个数据源要复制的只是**一个定时器加一次循环**，那点重复远比一个过早定型的契约便宜。等真有第二个源时，才会知道那个契约该长什么样。

另一条被收回的理由：曾说"插件调内核等于方向倒了"。这站不住——`plugins/jira/server.ts` 已经直接 import 了 `ensureItemForSource`、`bindSession`、`resolveBindings`，插件依赖内核正是既定且正确的方向。`ensureItemForSource` 本身就是"按 `(provider, ref)` 建或更新"，连接器不过是在定时器里循环调它。

## `start()` 钩子

`plugins/handlers.ts` 的 `PluginServer` 加一个可选能力：

```ts
export type PluginServer = {
  handle?: PluginHandler;
  enrich?: PluginEnricher;
  /** 进程启动时调一次。插件想要后台循环，自己在这里起。 */
  start?: () => void;
};
```

内核对它的了解到此为止——不懂拉取、不懂调度、不懂失败。只是"启动时给插件一次机会"。

**调用点在 `src/index.ts`，不在 `startServer()`。** 这条沿用第 1 期的教训：至少五个测试文件直接调 `startServer`，钩子挂在那儿就意味着跑一次 `bun test` 会拿真实 token 发请求、往真实的 `~/.tmux-next/items.json` 写单。迁移当初正是栽在这上面，`migrateJiraBindings()` 因此被移到 CLI 入口。`src/index.ts` 是唯一的 bin 入口，只有真启动才走。

**包 try/catch**：一个插件的 `start()` 抛了不能挡住服务器起来。失败语义仍然唯一——**这个插件没有后台任务，其它一切照常**。

一条守卫测试钉住落点：断言 `src/server.ts` 不 import 插件的 start 路径。跟第 1 期钉迁移落点那条同款——不钉住的话，一次"顺手收拢启动逻辑"的重构就能把它挪回去，而全套测试照样绿。

## 连接器

`plugins/jira/server.ts` 导出 `start()`，里面起一个循环：

```
启动后立刻一次，之后每 5 分钟：
  按 config.jql 拉工单             ← 已有的 fetchIssues
  写进已有的 60 秒工单缓存          ← enrich 从这里读，不改
  对每条工单 ensureItemForSource("jira", key, summary, { refreshTitle: true })
  给「有活跃会话」的单拉 PR 状态，写进已有的 dev 缓存
```

三件事都用现成的：`fetchIssues`、那两个内存缓存、`ensureItemForSource`。**新代码只有循环本身。**

**立刻拉一次，不等满一个周期**：否则新装的实例首页是空的，而空首页看不出是"没单"还是"还没拉"。

### `ensureItemForSource` 要能更新标题

它现在是"有就返回、没有就建"，标题不更新——工单改了名首页就一直是旧的。加一个可选参数：

```ts
ensureItemForSource(provider, ref, title?, opts?: { refreshTitle?: boolean })
```

`refreshTitle` 只碰 `title`，**绝不碰 `cwd`、`tags`、`closedAt`**。那三样是本地状态，是你在这个工具里投入的东西，远端的一次改名不该动它们。这条要有测试，而不只是有注释。

### 一次拉取最多建 200 张单

一条写错的 JQL 能返回几千条，而 `items.json` 是纯文本全量读写。超过就截断。

**截断必须打日志说出来。** 静默截断会让页面看起来像"就这么多"——这个仓库在 `checksKnown` 上已经守过同一条线：「我们没问到」和「没有」是两回事，收成一个会让页面往好看的方向撒谎。

### PR 状态只给有活跃会话的单拉

`jira.prs` / `jira.checks` 已经实现，但它们读的 `devCache` 只有打开工单页才会被填，所以首页上现在没有 PR。

让连接器顺便拉的代价是：一个单一次 dev-status，每个 PR 再一次 Bitbucket。41 个单是上百次请求，每 5 分钟一轮——这正是原设计拒绝开页即拉的原因。

所以只给**有活跃会话绑定**的单拉。这一条同时解决两件事：你真正盯着 CI 的那个 PR，一定是你正开着会话在做的那个；而请求数从"你有多少工单"（41，还会长）变成"你开着几个会话"（通常个位数）。其余的单在你打开工单页时按原有路径拉，一个字不改。

## assignee 维度

`Issue` 现在带 `{id, key, summary, status, statusCategory, updated, parent}`，没有 assignee。`client.ts` 要多要一个字段、多解析一个，`facetsFor` 多产一个 `jira.assignee`，`plugin.js` 的 `facetDims` 与两份字典各加一条。

这是这次唯一动到 Jira 数据形状的地方。

**取值可能只有一个，那不是问题。** 默认 JQL 是 `assignee = currentUser()`，此时这个维度只有你自己。筛选区是**按需添加字段**的，废维度不加就是了。想让它有意义就把查询放宽——那是配置的事，不是代码的事。

## 归档入口

「工单消失时什么都不做」意味着已完成、已转派的单会永久留在首页。必须有手动清理的办法，否则首页会慢慢烂掉。第 1 期给了 `closedAt` 和 `PATCH /api/items/:id`，至今没有 UI 能设它。

- 卡片上一个「归档」动作，写 `closedAt`
- 工具栏一个「显示已归档」开关，逐设备记住（跟分组、筛选、字段同一套 `localStorage`），关着时不画

**归档不是删除**：会话绑定、标签都在，取消归档就回来。这条继承第 1 期。

## 失败边界

单已经落盘，所以失败一律不影响你看到什么：

| 情况 | 行为 |
|---|---|
| Jira 连不上 / token 被吊销 | 单照常在，少几个 facet，日志一条。**绝不因为拉不到就删单** |
| 没配置 Jira | `start()` 立刻返回，不起定时器 |
| 只拉回一半 | 无害——从不删，所以"这次没看到"和"不存在"不需要区分 |
| 超过 200 条 | 截断 + 日志说出来 |
| `start()` 抛了 | 这个插件没有后台任务，服务器照常起 |

"只拉回一半无害"这一点，正是「消失时什么都不做」那条取舍换来的好处：内核不需要理解"一次拉取算不算完整"，也就不会把超时截断误判成工单失踪。

## 测试

- **`start()` 钩子**（内核）：一个会抛的假插件 → 服务照常起；一个正常的 → 只被调一次。用 `enrich` 那套注入假插件的做法，理由相同——注册表是编译期常量，没有注入就没法证明安全阀会触发。
- **落点守卫**：断言 `src/server.ts` 不 import 插件 start 路径。
- **同步循环**：抽成纯函数 `syncIssues(issues, ensure)`，无网络可测——标题会更新、`cwd`/`tags`/`closedAt` 不被碰、超 200 条截断且报出来。
- **assignee**：`facetsFor` 多一条断言。
- **PR 只给有会话的单拉**：喂一批单加一批绑定，断言只对有活会话的那些发起 dev 请求。
- **归档**：happy-dom——点归档后卡片从默认视图消失，开关打开后回来。
- i18n 与主题：新键两种语言都要有且真被引用；新样式不许有颜色字面量。

## 不做

- **不做 provider 契约**（`provide()`）。理由见上；真有第二个数据源时再看那时的形状。
- **不做写回 Jira**：不改状态、不写评论、不记工时。写操作发生在一个无认证的服务里，风险面完全不同。
- **不自动删单、不自动归档**。使用者选的。
- **不做配置 UI**。`config.json` 仍然手改，跟今天一样。
- **不改 `enrich` 的规矩**：它仍然禁止发网络请求，仍然只读缓存。连接器是另一条路，不是它的放宽。
