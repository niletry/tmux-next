# Jira 工单插件：从工单开会话，并按工单管理会话

## 问题

工作是按工单来的，会话是按 tmux 来的，中间没有东西把两者连起来。于是现在的做法是**拿单号当会话名**——`DL-ENG-45138`、`ENG-45102`、`DL-ENG-44134 done`。

这是个无奈之举，代价具体且已经在付：

- **tmux 会话名必须唯一，所以一个单只能有一个会话。** 一个单要开两个会话（比如一个跑测试、一个改代码）就没了名字可用。这是最贵的那条。
- 会话名被单号占死，写不了人话。列表里一眼看不出哪个是哪个。
- 单的标题和状态只在 Jira 里，手机上要对照就得开浏览器。

要的是：手机上看到分给我的单，点一个就能开会话；开完之后，会话列表里每一行都知道自己属于哪个单。

## 已定的取舍

四条在设计对话里定死，不再重开：

- **只做"从工单开会话"**，不做双向回写（改状态、写评论、记工时）。写操作发生在一个无认证的服务里，风险面完全不同，要做也是另一个 spec。
- **绑定关系独立存**，不再靠会话名编码。会话名因此重新自由。
- **不上数据库。** 数据量由"你有多少个 tmux 会话"封顶——现在 29 个，永远是几十条。`bun:sqlite` 虽是 Bun 内置、不算新依赖，但仓库里每一处状态都是能 `cat` 出来看、坏了直接删的纯文本（`sessions/`、`pins.json`、`notifications.jsonl`、`theme.json`、`asr.json`），引入二进制格式会破坏这个一致性并多出迁移问题。真到几千条那天再换，届时数据结构也更清楚。
- **Jira Cloud REST API + API token**，Basic 认证。

## 一个单可以有多个会话

这是设计的轴心，不是边角情况。

绑定文件因此**按会话作键**：N 个会话指向同一个单是天然的；反过来存（工单→会话数组）每次会话改名或消亡都要去数组里翻。

UI 上也跟着变：工单是一组，组内挂它的会话，旁边永远有「再开一个」——不是「打开」。多开是常态。

## 凭据与配置

`pluginStateDir("jira")` → `~/.tmux-next/jira/`（`TMUX_NEXT_JIRA_DIR` 可覆盖），里面 `config.json`：

```json
{ "url": "https://example.atlassian.net", "email": "dev@example.com", "token": "…", "jql": "…" }
```

写入时 `chmod 0600`，跟 `asr.json` 同一套。

**运行时不读 `~/.claude/credentials.md`。** 那是 Claude Code 的约定文件，理由三条：解析自由格式 Markdown 取凭据，格式一飘就坏；它是**总账**（"all service credentials"），让一个无认证服务去读它，等于把暴露面从 Jira 一家扩大到里面所有服务；而 `asr.json` 已经是严丝合缝的先例。首次配置可以从那份文件把三项搬过来，一次性的，之后互不相干。

**没有任何接口回显 token。** `GET /api/jira/config` 只返回 `{ configured, url, email }`。

未配置时 **tab 仍然显示**，页面讲怎么配。这里故意不跟麦克风按钮的先例一致——那条规矩是"只会失败的按钮不如没有"，但 tab 是你唯一能发现这功能存在的地方，藏了就没人配得起来。

## 拉取与缓存

浏览器**永不**直连 Jira：token 会漏，CORS 也不通。服务端代理。

`GET /api/jira/issues` 跑配置里的 JQL，返回裁剪过的形状，只有渲染要用的字段：

```ts
type Issue = { key: string; summary: string; status: string; statusCategory: string; updated: number };
```

默认 JQL：`assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC`。

**只跑配置里的 JQL，绝不接受浏览器传来的 JQL。** 否则这个无认证服务就成了一个任人查询的 Jira 代理——任何能碰到它的人都能把整个实例翻一遍。这条是安全边界，不是洁癖。

其余规矩：

- 内存缓存 60 秒，`?refresh=1` 强刷。**不落盘**：token 被吊销之后，磁盘上留着一份过期工单列表是纯负债，而重拉很便宜。
- 硬超时 8 秒（`AbortSignal.timeout`）。Jira 挂了不能把页面吊死。
- 错误归类后再吐：401/403 → 凭据无效；其余 4xx → 查询有误；超时/网络 → 连不上。**不透传 Jira 的原始错误体**，那里面会带账号信息。

## 绑定

`~/.tmux-next/jira/bindings.json`：

```json
{ "<会话名>": { "key": "EXAMPLE-1", "sessionId": "$7", "boundAt": 1787000000 } }
```

**名字和会话 id 都存，是为了改名。** `#{session_id}` 跨改名不变、跨 tmux server 重启会重排；名字反过来。解析时先按 id 认，认不上再按名字认——改名和重启各被覆盖一半。

这个双写是为了**避免给接缝再开一个"会话改名事件"的口子**。只按名字存的话，用户在终端页点一次改名，绑定就断了，而插件无从知道；补救办法要么是内核广播事件（新能力），要么是这个双写（零新能力）。选后者。

**会话 id 从哪来**：内核的会话列表不查 `#{session_id}`（`src/tmux/session-list.ts` 的格式串里没有它），所以插件自己跑一次 `tmux(["list-sessions", "-F", "#{session_id}|#{session_name}"])`。走的是 `src/tmux/run.ts` 的 `tmux(argv)`——插件依赖内核，方向正确，**不要为此往内核的列表里加字段**，那是内核为一个插件的需要长出概念。

写入走临时文件 + `rename`，避免并发请求写坏。

**回收**：会话消失不立刻删绑定。仓库里有会话恢复机制，一个指向已死会话的绑定恰好是"这个单之前开过，要不要恢复"这条信息。只有会话**既不在跑、也不可恢复**时才算陈旧，且只在用户明确操作时才清。自动删会把恢复入口一起删掉。

## 接缝新增：插件可以标注会话行

这是给刚建好的插件接缝开的第一个新口子，理由必须站得住：当初按 YAGNI 砍掉"跨页面挂钩"，是因为**没有消费者**。现在有了——而且不开这个口子，就解决不了"乱"。

乱是乱在**内核的会话列表页**。一个单挂三个会话时，列表里就是三行互不相干的东西。把工单视角单独做成一个页面（曾经的备选方案 A）非但没解决它，还多了一处要对照的地方。

### 接口

插件的 `server.ts` **可选**导出：

```ts
export async function annotate(sessions: string[]): Promise<Record<string, Annotation>>;

type Annotation = { text: string; detail?: string; tone?: "ok" | "warn" | "dim" };
```

内核构建会话列表时对每个启用的插件调一次，**硬超时 300ms，外面套 try/catch**。插件慢了、抛了、根本没导出这个函数，都当作没有标注：**列表照常渲染**。这是唯一的失败语义，不给插件拖垮内核页面的机会。

响应里按插件 id 分组：`annotations: { "jira": { "<会话名>": Annotation } }`。

前端 `list.js` 泛型渲染，**它不认识 "jira" 这个词**。文本一律走 `textContent` 并限长，插件不能往列表里塞标记。

口子的边界写死：**只读，只回展示数据**。插件不能改列表行为、不能加动作、不能排序。

## UI

新 tab `/p/jira/`：

- 工单一组，显示单号、标题、状态
- 组内挂它的会话：在跑的、已死可恢复的（后者标出来）
- 每组旁边永远有「再开一个会话」

### 建会话这一步的取舍

插件页**自己调内核公开的 `POST /api/sessions`**，参数与手工新建完全一致，目录选择复用内核那个已经被测过的纯模块 `dir-filter.js`；建成之后由插件自己写绑定。

代价是插件页与 `new.js` 会有一部分 UI 重复。

另一条路是让内核的新建页接一个 `?bind=` 参数、建成后回调插件——那需要给接缝开**第二个**口子（建后钩子）。一个功能里连开两个口子是坏味道，宁可吃这点重复。若将来第三个插件也要"建完之后做点什么"，那时才是把建后钩子做成正式能力的时候。

预填会话名从单号来，撞名就 `-2`、`-3`。`POST /api/sessions` 吃 `{ dir, name?, agent?, skipPermissions?, resume? }`、返回 `{ name, created }`——**名字冲突时内核不报错**，它会复用已存在的同名会话并把 `created` 置为 `false`；前端得自己接住这个 `created: false`，据此提示用户而不是当成新会话跳转过去。`reserved`/`invalid` 是另外两类真实错误（名字撞了内核自己的 `web-` 前缀、名字里带了 tmux target 里有特殊含义的字符），不是名字冲突走的路径。

## SECURITY.md 要补的

- 这台机器上现在有一份 Jira 凭据。**任何能碰到这个服务的人，即使拿不到 token 本身，也能通过这些接口以你的身份读 Jira。** `--host` 的警告和反代认证，从"保护你的 shell"升级为"还保护你的 Jira"。
- JQL 不接受外部输入，以及为什么：否则它就是个查询代理。
- `config.json` 是 0600，且从不进日志。

## 测试

前提：**一次真实的 Jira 请求都不发。**

| 测什么 | 怎么测 |
|---|---|
| Jira 客户端 | 所有 HTTP 走一个可注入的 fetcher，测试注入假的。覆盖 401/403、4xx、超时、畸形 JSON |
| 错误归类 | 断言吐出去的是归类后的原因，且**不含** Jira 原始错误体 |
| 绑定存储 | env 覆盖目录，直接测。含改名（按 id 认回）、重启（按名字认回）、并发写 |
| 陈旧判定 | 会话不在跑 + 不可恢复 → 陈旧；不在跑但可恢复 → 不算 |
| 标注能力（内核侧） | 一个会抛异常的插件、一个会超时的插件，**都不能让会话列表出不来** |
| 夹具卫生 | 正向规则：插件源码与夹具里出现的域名只允许 `example.` 开头 |

最后一条是正向规则而非黑名单，因为**写黑名单等于把公司名写进公开仓库**，正好犯了要防的那件事。这个仓库的历史被清洗过一次（工单号、公司名、主机名、真实路径），不能重新引入。夹具一律 `EXAMPLE-1`、`https://example.atlassian.net`、`dev@example.com`。

## 不做什么

- 不做双向回写（改状态、评论、工时）
- 不做工单搜索框：JQL 在配置里，浏览器传 JQL 是安全边界外的事
- 不把工单描述喂给 agent：一大段可能过时的正文塞进上下文窗口，弊大于利。要看描述就点开单
- 不做前缀→目录的映射：建会话的参数走手工那套就够了
- **不做**存量会话的自动识别。从 `ENG-123` 这样的旧名字认出单号并建议绑定，是个独立的、可有可无的便利功能，不在本 spec 范围内；现有会话手动绑一次即可。长期机制是绑定文件，不是名字
