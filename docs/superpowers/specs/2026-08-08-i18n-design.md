# 界面多语言（中文 / 英文）

## 问题

界面文案全是中文，而 README 是英文、包发在 npm 上。国际用户装完打开就是一屏看不懂的字，而作者自己需要中文。这两个需求同时存在，所以不能靠"改成英文"解决——必须并存。

实测规模：

| 位置 | 中文处数 |
|---|---|
| 前端 JS（7 个文件） | 约 160 |
| 前端 HTML（4 个文件） | 37 |
| `push.ts` 推送文案 | 4 |
| `hook-setup.ts` CLI 输出 | 5 |

其余中文都在测试断言里，不面向用户。

## 语言存哪

新建 `~/.tmux-next/language.json`，与 `theme.json` 平行，路径可用 `TMUX_NEXT_LANG_PATH` 覆盖——与其余 8 个状态文件同一约定。

不塞进 `theme.json`：那个名字只表示配色，混入语言以后加第三个设置只会更乱。

**首次访问按 `Accept-Language` 猜一次并存下来**，之后以存的为准。国际用户装完直接是英文，作者不受影响。选择是机器级的，和主题一致——理由相同：「这台机器长什么样」与「这块屏幕多大」是两件事，语言属于前者。

## 取词

`public/i18n.js`：两本字典加一个 `t(key)`。纯数据、无 DOM 依赖，因此可被 `bun test` 直接覆盖——与 `themes.js`、`terminal-fit.js` 同一模式。

HTML 里的静态文本用属性标注，启动时统一替换，而不是把 HTML 拆成 JS 字符串：

```html
<span data-i18n="sessions">tmux 会话</span>
<button data-i18n-aria="newSession">＋</button>
```

`data-i18n` 换 `textContent`，`data-i18n-aria` 换 `aria-label`，`data-i18n-title` 换 `title`。HTML 里保留中文原文作为兜底——脚本没跑起来时页面仍然可读，而不是一片空白。

## 必须有的一条测试

`terminal.js`、`list.js`、`create-sheet.js` 不做类型检查（`checkJs: false`）。这意味着 `t("newSesion")` 少一个字母**不会有任何报错**，界面上只会显示空白或 key 本身。200 处机械替换里出这种错几乎是必然。

所以：

1. 扫描 `public/` 下所有 `t("…")` 与 `data-i18n*="…"`，断言每个 key 在**两本**字典里都存在
2. 反向扫描字典，报出没有任何调用点引用的死 key
3. 断言两本字典的 key 集合完全一致

第 3 条单独列是因为漏译不会报错——英文字典缺一个 key 时，英文用户看到的是中文，而中文用户一切正常，作者永远发现不了。

## 推送文案也纳入

`push.ts` 那 4 处会推到锁屏，是唯一脱离界面出现的文本。界面英文、锁屏中文最突兀。服务端读同一份语言设置。

`hook-setup.ts` 的 5 处是 CLI 输出，直接改英文、不进字典——命令行与 README 保持一致即可。

## 分三步

| | 内容 | 完成标志 |
|---|---|---|
| 1 | i18n 基础设施、语言存储、上述测试、切换入口 | 切换生效，字典完整性有保障 |
| 2 | 前端约 200 处替换，按文件推进 | 每个文件替换后 key 检查通过 |
| 3 | 推送文案与 CLI | 锁屏通知跟随语言 |

第 1 步先建安全网，第 2 步的机械替换才不会漏。

## 切换入口

放进现有的「外观」弹层，标题改为「设置 / Settings」，内含语言与主题两块。不新增顶栏图标——顶栏已有 5 个，再加会挤，而语言和主题都是设一次基本不动的低频项。

## 不做什么

- **不做第三种语言**。字典结构支持，但目前没有需求，YAGNI。
- **不翻译 agent 自己的输出**。终端里显示的是 Claude/opencode/pi 的文本，与本项目无关。
- **不翻译 README 之外的文档**。`docs/` 是给开发者看的。
