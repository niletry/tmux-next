# 在目录选择里创建新目录

## 问题

新建会话时只能从已有目录里挑。要给一个还没建目录的新项目开会话，得先退出去、找个终端 `mkdir`、再回来——而手机上根本没有"另一个终端"可退。

## 交互：复用筛选框，不加新控件

想建 `foo` 的人，自然动作是在筛选框里打 `foo`，然后撞上空状态：

```js
// 现状
if (!matches.length) {
  list.replaceChildren(el("p", "dir-empty", entries.length ? "没有匹配的目录" : "没有子目录"));
}
```

把这个空状态变成可点的 `＋ 在这里创建 foo/`，只在 `foo` 是合法目录名时出现。点击 → 创建 → 自动进入该目录，后续流程不变。

这样手机上省掉了"点按钮 → 弹输入框 → 再打一遍名字"整整一轮：名字用户已经打过了。

## 服务端：`POST /api/dirs`

Body `{ parent, name }`。三层校验，缺一不可：

1. **`parent` 走现有的 `resolveDirectory`** — 必须已存在、是目录，并取得 realpath 规范化后的路径。复用而非另写，是为了让"会话起在哪"和"目录建在哪"经过同一套解析。
2. **`name` 走新的纯函数 `validateDirName`** — 非空、不含 `/`、不是 `.` 或 `..`、不以 `.` 开头（列表本就不显示点目录，建了看不见）、长度 ≤ 255。
3. **`join(parent, name)` 之后确认 `dirname(结果) === parent`** — 兜底。即便前两层被绕过，结果也必须仍在用户正看着的那个目录下。`mkdir` 不带 `recursive`，建不出层级。

第 3 条是关键：它把"这个端点不能变成 `mkdir -p`"变成**结构性保证**，而不是依赖字符串校验写得足够全。字符串校验会漏（Unicode 变体、平台差异），路径比较不会。

目录已存在返回 **409**，不静默当成功——否则用户以为建了新目录，实际进了别人的目录。

## 为什么这不扩大攻击面

`CLAUDE.md` 与 `paths.ts` 已经确立：不做目录白名单，理由是"能访问这个界面的人本来就能 attach 会话敲 `ls`"。同样的推理适用于写操作——能 attach 就能 `mkdir`。这个端点给出的能力，是使用者已经拥有的能力的子集（更窄：只能建一层，不能删、不能改）。

`/api/upload` 已经在往磁盘写文件，所以这也不是开先例。`SECURITY.md` 从未声称只读，不需要修改。

## 测试

重点在 `validateDirName`：纯逻辑、可穷举。必须拒绝 `../etc`、`a/b`、`.`、`..`、``、`   `、`.hidden`、超长名；必须接受含空格、含中文、含 `-`/`_` 的正常名字。

外加一条集成测试：以 `..` 之类作 name 调用 `createDirectory`，断言 parent 之外没有任何目录被创建——直接验证第 3 层兜底，而不只是相信第 2 层。

## 不做什么

- **不做 `mkdir -p`**。手机上敲多级路径本就痛苦，而一次手滑能在文件系统深处造出一串目录且难以察觉。
- **不做删除或重命名目录**。建目录的误操作代价是一个空目录；删除不是。
- **不做点目录**。列表不显示它们，建了等于消失。
